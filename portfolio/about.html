关于我：从 iOS 开发到 AI 驱动的完整交付

十三年以上工程经验，三个相互衔接的职业阶段。

我的职业主线

我是盖剑秋，一名拥有十三年以上经验的软件工程师。我从 iOS 开发起步，逐步将工作拓展到智能设备、安全 SDK 与全栈开发。

回顾职业经历，我将它分为三个阶段：首先是电商应用开发，其次是智能设备连接与可复用 SDK、模块建设，最近则是安全研发，以及借助 AI 编程工具完成整套系统交付。

第一阶段：电商开发，让我学会从用户出发

在途牛和有货，我参与的都是电商业务，但面向不同的用户和场景：途牛聚焦旅游，有货聚焦潮流时尚。

在途牛，我参与 iPad 购物体验与旅游详情页开发，建立了扎实的 iOS 基础，尤其是 Objective-C、页面行为与应用生命周期。

在有货，我继续开发购物功能，同时参与 React Native、直播推流、微信小程序与原生 A/B 测试。这些经历拓宽了我对移动开发和功能交付方式的理解。

这一阶段最重要的收获，是学会站在用户的角度思考。功能不仅要正确运行，还应清晰、流畅、易用。直到今天，我仍将这份对用户体验的关注融入工作，以像素级标准打磨界面细节、交互反馈与操作流畅度。

第二阶段：智能设备与 SDK，让能力成为可复用的组件

随后，我先后在涂鸦智能与华米从事智能设备相关研发。

在涂鸦，我开发维护面向智能设备的商用 SDK，工作涉及 Wi-Fi 配网、设备功能维护，以及为企业客户应用提供支持。我也参与了与 Alexa、Google Home 相关的设备账号绑定集成。

这与开发应用页面是不同的挑战：设备可能离线，连接可能失败，任务也可能晚于预期完成。因此，我需要仔细处理连接状态、异常与兼容性。

我也逐渐学会从 SDK 使用者的角度思考：接口应容易理解，行为应可以预期，文档应帮助开发者解决问题。

在华米，我使用 Swift 与 SwiftUI 开发小米运动和 Zepp，工作覆盖健康、表盘、实验室、世界时钟，以及蓝牙设备集成。

我还负责设备功能模块化项目。除了写代码，也拆解任务、协调资源、跟踪交付进度。这一阶段帮助我从实现单个功能，走向设计能够服务不同设备与产品的可复用组件。

第三阶段：安全与 AI 全栈研发，对完整系统负责

2022 年 4 月至 2026 年 10 月，我在国网电力科学研究院驻场项目中从事移动安全、安全通信，并逐步拓展到全栈开发。

在移动端，我维护安全接入 SDK，并研发 iOS 安全监测 SDK。在供应商停止支持后，我独立研发核心安全库，检测越狱、调试、代码注入及关键系统函数遭到修改等风险。

安全不只是发现风险，也要保持正常应用的稳定。我既测试风险样本，也测试正常设备，排查误报，并检查应用前后台切换等场景下的行为。

我也处理安全网络连接问题，例如手机在 Wi-Fi 与蜂窝网络之间切换时的连接失败，或多个重连请求并发触发的问题。这类排障经常需要从 Objective-C 一路追踪到 C 或 C++。

近期的 API 安全监测项目，体现了我从移动研发向完整系统交付的拓展。我主要使用 Claude Code 和 Codex，独立完成数据处理链路、既有 Web 应用改造、测试与内网部署。项目原预计约半年完成，实际三周交付。

系统采集网络数据、处理 API 请求，并通过 Web 界面展示 API 资产与安全风险。我使用 Java 和 Flink 处理数据，使用 Elasticsearch 存储与检索，通过 Docker 完成部署。

AI 帮助我编写重复代码、探索不熟悉的技术栈、准备测试脚本和文档；我负责定义任务、作出设计决策、审查结果，以及验证系统实际运行行为。

例如，图表看起来正确，并不代表数字正确。我需要沿数据链路追查重复计数、时区差异等问题。这让我更重视以实际可用的结果和可靠的数据衡量进度。

我也承担过移动端组长和研发组副组长职责。我喜欢保持对代码的直接参与，同时帮助团队组织工作、讲清技术问题。

我能为下一支团队带来什么

这三个阶段自然衔接：电商让我关注用户，智能设备与 SDK 让我重视可靠连接与组件复用，安全及全栈研发让我对完整系统承担责任。

我最扎实的基础仍是 iOS 与原生开发。同时，当项目需要时，我能够跨越应用、SDK 与后端开展工作。我愿意学习新工具，也善于利用 AI 加快研发，并始终对结果质量负责。

在下一份工作中，我希望将移动端经验、问题解决能力与 AI 辅助研发方法结合起来，帮助团队交付真正有用、可靠、体验流畅的产品。欢迎进一步交流这些项目与实践。
